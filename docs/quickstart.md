# 酒管同步：照着做就能用

**换设备前上传；换设备后检查更新、安排应用、手动重启服务，再继续聊。**

本说明对应 **1.4 统一安装向导**。已经装好可直接看[每天怎么用](#每天怎么用)。

## 第一次用：先准备好

- 只支持酒管 **1.17.x**，需要 **Node.js 20 或更新版本、npm 和 Git**。电脑还是旧版的，先备份并自行升级；安装向导不会替你升级酒管。
- 两台设备先备份酒管的 `data` 文件夹，首次用只含测试聊天的独立实例走完整个流程。
- 两端先导入同一张角色卡，**实际卡文件名也要一致，包括重名后缀**。只看角色显示名相同不够。
- 终端运行 `node -v`、`npm -v`、`git --version` 应能显示版本。缺工具时先按 [Node.js 官方指引](https://nodejs.org/en/download)和 [Git 官方指引](https://git-scm.com/downloads)安装；Termux 可用 `pkg install nodejs git`。

目前只同步**当前用户全部已保存的一对一聊天正文**，不只当前打开的聊天。角色卡、世界书、群聊、附件和设置不会一起过去。Termux 真机、真实 GitHub PAT 和真实聊天同步尚未完成验收。

## 第一步：建私有数据仓库和令牌

1. 打开 [GitHub 创建仓库页面](https://github.com/new)。填写 `jiuguan-chat-data`，选择 **Private（私有）**。
2. 不添加 README、`.gitignore` 或 License，创建空仓库。
3. 打开[细粒度令牌创建页面](https://github.com/settings/personal-access-tokens/new)，填写名称和有效期。
4. `Resource owner` 选择数据仓库所有者；`Repository access` 选 **Only select repositories**，只选刚建的数据仓库。
5. `Repository permissions` 中将 **Contents** 设为 **Read and write**；**Metadata 保持默认只读，不加其他权限**。
6. 生成并妥善保存令牌，稍后填进各设备。不要发送给别人，也不要截进图片。

**`ABGanBei/jiuguan-github-sync` 是公开插件代码仓库，不能填写到聊天同步的数据仓库栏。**

## 第二步：每台设备运行一次安装向导

1. 从[插件源码页面](https://github.com/ABGanBei/jiuguan-github-sync)的 **Code → Download ZIP** 下载并解压本版，或用 Git 克隆到一个新目录。
2. 关闭这台酒管的**所有页面和客户端**，并停止酒管服务。
3. Windows：打开解压后的目录，**双击 `install.cmd`**。Termux：进入源码目录，运行 **`bash setup.sh`**。
4. 按向导选择酒管目录，应能看到 `server.js` 和 `package.json`。再确认实际使用的 `config.yaml` 和数据目录（通常是酒管目录里的 `data`）；如果平时用了自定义启动路径，就填原来的路径。核对计划后确认安装，向导会一起安装前端和后台、安装依赖并启用服务端插件。
5. 安装完成后，按原来的方式手动启动酒管，再打开一个全新页面，找到「酒管 GitHub 同步」。

**不用再分别通过扩展 URL 和旧后台命令安装。** 向导支持首次安装和可识别版本的升级；同版本且内容一致时不重复安装。

如果提示**用户级同名扩展会遮蔽共享扩展**，先备份提示中的旧扩展目录，再卸载旧扩展，或将它移到 `extensions` 扫描目录之外。**仅在界面里停用不够，安装器仍会阻断。** 未知来源、修改过或没有安装清单的旧目标默认拒绝覆盖；只有确认要接管时才使用 `--takeover`，向导会先完整备份旧目录。不要直接删除安装目标目录来绕过检查。

## 第三步：先设置有聊天的那台

面板的首次设置分三步：准备仓库、填写并验证、查看结果。

1. 数据仓库填自己的 `owner/jiuguan-chat-data`，分支默认 `main`，填入令牌；自动检查先保持关闭。
2. 点 **「保存并验证」**。成功保存后令牌框清空，留空表示保留已保存的令牌。
3. 如果提示所选分支不存在，核对目标后勾选初始化确认，再点 **「确认初始化分支」**。这会普通推送一个**不含聊天**的初始化提交，不强制覆盖。
4. 查看结果。**私有仓库已确认、读取已验证，不等于写入已验证，也不等于聊天已同步。** 只有实际初始化或实际上传成功，才会确认写入；分支保护等规则仍可能拒绝推送。
5. 等回复生成、聊天保存完成，点 **「上传已保存聊天」**，确认结果成功且没有冲突。

另一台填写**同一个私有仓库、同一个分支和有权限的令牌**，点「保存并验证」。仓库已有该分支时不用再初始化。然后按下面的接收流程检查更新，再继续聊天。

已有同步状态后，仓库和分支会锁定；可更新令牌并重新验证，本版不提供直接切换目标或清除历史。

## 每天怎么用

日常主要使用 **「上传已保存聊天」** 和 **「检查更新」** 两个按钮。以电脑换手机为例：

**电脑上：** 等生成和保存完成，点「上传已保存聊天」，确认成功、没有冲突。

**手机上：**

1. 先别继续聊天，点 **「检查更新」**。
2. 有已暂存的待更新聊天时，查看列表，点 **「检查待更新项」**，确认预检通过。预检只反映当前状态，安排和启动时还会再次核对。
3. 关闭访问这台酒管的其他客户端和旧标签页，勾选确认，再点 **「安排应用（重启后）」**。
4. 看到安排成功后，关闭当前页面，**手动停止酒管服务，再按原来的方式启动**。
5. 打开全新页面，确认最近应用状态，再进对应角色的聊天历史继续。

手机换电脑时把两边对调。没有新内容就不用安排应用。**检查更新只暂存，尚未改写聊天；安排成功也还没完成同步；刷新网页不算重启服务。** 不要两台同时修改同一段聊天。

自动检查藏在「自动检查与其他设置」中，默认关闭。打开后只定时检查并暂存，**不上传、不在线覆盖、不自动应用**；已安排应用时保留当前暂存。服务关闭或手机休眠时不保证运行。

如果提示「上次上传尚未确认」，检查更新会暂停。核对目标后点「上传已保存聊天」明确重试；插件会先核对上次结果，保留未确认内容。

## 安装中断或需要恢复

保留安装目录、报错和 `<酒管目录>/.jiuguan-install/`。在本版源码目录运行，路径替换成自己的；执行恢复或回滚前都要先关闭所有页面并停服：

```text
node bin/setup.js --status --app-dir "酒管目录"
node bin/setup.js --recover --app-dir "酒管目录" --stopped-confirmed
node bin/setup.js --rollback --app-dir "酒管目录" --stopped-confirmed
```

先用 `--status` 查看，再按情况选择恢复未完成安装或回滚；**不要把上面三行当作必须依次执行的步骤**。回滚默认使用当前事务或最近备份，需要指定备份时加 `--to <backupId>`。历次备份会保留，回滚后的新版目录也会移入隔离目录保留。

如果安装时选择了酒管目录以外的配置文件，恢复或回滚时再加 `--config "原来的config.yaml完整路径"`。

## 卡住了怎么办

| 看到的问题 | 怎么做 |
| --- | --- |
| 缺少后台、能力不足或按钮不可用 | 确认两台都运行了本版向导，已手动重启服务并打开全新页面；检查用户级同名扩展遮蔽提示。 |
| 版本不支持 | 备份后自行升级酒管至 1.17.x，向导不会代做升级。 |
| 目录无法识别、被修改或有未完成安装 | 保留目录和报错，先查看安装状态；不要直接删目录或反复重装。 |
| 验证或上传失败 | 核对私有仓库名、分支、网络、令牌有效期、所选仓库和 Contents 读写权限；读取成功不保证能推送。 |
| 冲突、删除待处理、预检失败 | 停止同步，保留两边数据和报错，排查后再继续；不要强行覆盖。截图先遮住令牌。 |

聊天以**明文进入 Git 历史**，私有仓库没有额外加密；删除当前文件也不会清掉旧提交里的记录。安装向导不会自动停止或重启酒管服务。
