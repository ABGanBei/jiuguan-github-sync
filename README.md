# 酒管 GitHub 同步

[English](README_EN.md) | 中文

**第一次用？先看 [新手使用说明：照着做就能用](docs/quickstart.md)。**

> 本仓库是**同仓库双组件**：一个前端扩展（酒管界面集成）+ 一个服务端插件（后台 Git 与文件操作）。
> 两者需分别安装到酒管宿主。当前为 **1.3.0-preview.1 界面集成预览**，仅支持**一对一角色聊天正文**的同步，
> 且**不做在线原位 apply**。请在真实使用前完整阅读本说明与 [docs/integration-contract.md](docs/integration-contract.md)。

---

## 这是什么

酒管同步把**一对一角色聊天正文**备份到你的 GitHub 私有仓库，并可在多台设备之间安全地取回。
它**不是**把聊天数据实时覆盖的在线同步：拉取只会**暂存（stage）**到本地，真正的写入要等下次重启时在
服务启动的早期窗口内完成，并严格要求先关闭所有其他客户端与旧标签页。

**首版边界（务必理解）**：

- **只同步一对一角色聊天正文**（`chats/**/*.jsonl`）。角色卡、世界书、群聊正文、知识库、设置等**不同步**；
  使用前需保证两端配置了**相同的角色**，否则聊天与角色对不上。
- **无在线 apply**：UI 里没有“下载即覆盖本地聊天”的按钮，下载只暂存。
- **无 force push / force pull**：不会强制覆盖远端或本地历史。
- **删除不传播**：本地或远端删除某个聊天，不会扩散到另一端。
- **冲突保留双方**：发生冲突时不自动选边，保留双方内容供你手动处理。

## 安装（双组件）

同仓库两样东西，分开装。**首装**请先 `git clone` 本仓库并 `cd` 进入仓库目录，再按下面两步执行。

> 本仓库是**公开的插件源码仓库**（`github.com/ABGanBei/jiuguan-github-sync`）；聊天同步请**另建一个专用私有数据仓库**，配置里的 **Repository 不可填本源码仓库**。

### 1. 前端扩展（酒管界面）

在酒管「扩展」界面用**扩展 URL** 安装方式，粘贴本仓库的 Git 地址：`https://github.com/ABGanBei/jiuguan-github-sync.git`。
具体入口以你使用的酒管版本为准。

### 2. 服务端插件（后台）

在已克隆的仓库目录内，执行一次性 Node 安装器，把插件装到酒管 `plugins/` 目录并启用服务端插件：

```bash
git clone https://github.com/ABGanBei/jiuguan-github-sync.git
cd jiuguan-github-sync
node bin/install-plugin.js --app-dir <酒管应用目录> --enable-server-plugins --install-deps --apply
```

- **默认是 dry-run**：不加 `--apply` 时只打印 source/target/config 的精确计划，不写任何文件。实际安装必须显式加 `--apply`；建议先**不带 `--apply` 看计划**再带 `--apply` 落地。
- `--enable-server-plugins` 会把 `config.yaml` 的 `enableServerPlugins` 从 `false` 改成 `true`（幂等）。
- `--install-deps` 会在新插件目录执行 `npm ci --omit=dev`。
- Windows PowerShell 下可运行；Termux 支持为**设计 + 合成路径测试**，**尚未在真实手机实机验收**（安装器为纯 Node，见「验收状态」）。

> 安装完成后，请**关闭所有旧标签页 → 停止酒管服务 → 重启服务 → 重新新开页面**，让新前端扩展与服务端插件正确加载。

### 3. 配置

在酒管扩展界面里配置：

- **Repository**：`owner/repo`（指你**专门为聊天同步新建的私有数据仓库**，**不要填本公开源码仓库**）；**Branch**：`main`（或你的分支）。
- **PAT**：粘贴个人访问令牌。令牌**只写**到独立 secrets 存储（不进 settings/日志/仓库/URL/进程参数）；前端**不回填**已保存的令牌；留空表示保留既有令牌不变。
- 首次可勾选**初始化空分支**：只有在明确勾选时，才在空仓库 bootstrap 一次普通 push（**不 force**）。

### 隐私说明（使用前必读）

- **使用专门的私有数据仓库**：不要把聊天同步进其他代码/文档仓库。
- **令牌用 fine-grained PAT（细粒度令牌）**，并**只勾选该仓库的 `Contents` 读/写**即可（`Metadata` 由 GitHub 隐式只读，无需额外勾选）。**不需要**组织、账户或其它仓库的权限，也**不要**用 classic 全仓库权限的令牌。
- 确认该仓库**没有 ruleset 保护**阻止普通 push（否则推送会因权限被拒）。
- **私有仓库的访问控制 ≠ 端到端加密**：聊天会以**明文**进入 Git 历史；删除文件**不会**删除旧 commit 里的内容。
- 本版本**未加密、未做历史清理、无旧版 GUI 恢复**；若你有强隐私/加密需求，请先不要同步真实数据。

## 界面操作

| 操作 | 含义 |
|------|------|
| 保存 | 写入 repo/branch/自动检查设置与 PAT（PAT 只写到独立 secrets，前端不回填，留空保留） |
| 连接 | 测试仓库与令牌；可勾选“初始化空分支” |
| 上传已保存聊天 | 把磁盘上**已保存**的聊天推送到远端（push） |
| 检查下载 | 从远端拉取并**只暂存（stage）**，不写聊天 |
| 安排重启应用 | 绑定当前 stage 与目标身份/摘要，安排在下一次服务启动时应用；要求**关闭所有客户端并重启后重新打开** |
| 取消安排 | 仅清除安排，不删除已暂存的备份 |

**自动检查**默认**关闭**；开启后只定时 `pull` 暂存，**绝不自动 apply**。软件关闭或手机休眠期间不保证定时任务运行。

## 真正应用聊天（重启时）

因为**启动期的早期窗口是唯一安全写入聊天的时机**，安排的应用不会“无感在线覆盖”：

1. 在 UI 点「安排重启应用」，确认你会在重启前**关闭所有其他客户端与旧标签页**。
2. **关闭酒管服务**。
3. 重新启动酒管；插件会在官方 1.17 的 `loadPlugins` 等待窗口内、`listen` 之前，校验相同 stage/身份/摘要后完成写入。
4. 重新打开浏览器标签页。

如果校验失败（stage 或身份不符、聊天已被改动等），插件会保留原意与旧基线，**不会用当前内容改写期望值绕过**；
已发生部分写入时会阻止宿主继续启动，避免半写状态。

**收据（receipt）窄窗口限制**：应用完成后、落盘收据（receipt）之前的崩溃窗口内，聊天数据其实已经写入，但下次启动时插件**无法确认**这次应用已完成，
会保留安排并明确提示「无法确认，可在 UI 取消」，**绝不从历史 complete 记录猜测成功**。这是有意保留的产品限制（宁可让用户手动确认，也不冒认成功或永久阻断整宿主）。

## 安全边界

- 凭据经 `GIT_ASKPASS` 传递，PAT 不进配置、settings、日志、仓库、URL 或进程参数；Windows 下用 DACL 收紧到**当前用户 / SYSTEM / Administrators**（并清掉继承与其它显式宽读 ACE），非「仅当前用户」。
- Git/核心在专用 worker 中执行，清理继承的 token/GIT 配置/askpass/SSH 变量，禁交互；存储路径拒绝符号链接/junction/越界。
- 每用户独立配置、仓库与锁。

## 验收状态

- **已验收（官方隔离宿主 + 合成数据 + 本地 bare）**：官方 1.17 隔离宿主（固定提交 `e3f41666c69db032e17e079fcddcf40cf47e8593`）上，前端扩展经扩展 URL 从本地 Git fixture 安装 manifest/client；真实 Node 后端安装器 `--apply --install-deps` 启用并备份 config；真实 UI 保存合成 token 后清空不回填、CSRF 连接 bootstrap 本地 bare、push；另一端合成修改主线/分支、pull 仅暂存（磁盘未变）；UI 安排、关闭全部旧标签停服务、重启 listen 前 apply、全新标签载入主线第二候选 2/2、`/send` 追加用户消息成功保存；随后在 UI 再次 push，bare 远端文件与宿主保存字节**完全相同**，`swipes2`/`swipe_id1`/`swipe_info`/`peerNote` 均保留（证据见独立验收证据包 `host-continued-evidence.json`，由 Codex 随证据 ZIP 单独提供，**不随本源码包发布**）；真实 chat-manager 打开同步分支正文后 `/checkpoint-exit` 回主线成功（以上分支场景仅限定该合成主线/分支样本，**不代表所有分支场景均已验证**）。自动检查的定时器已用可控时钟验证退避与重启恢复。
- **未验收**：真实用户安装、真实手机（Termux 实机）、真实 GitHub PAT、真实 GitHub bootstrap 的 HTTP 鉴权 push 均**未验收**，请勿在真实手机/生产环境使用。Termux 的支持目前仅为设计 + 合成路径测试，未实机。
- **软件关闭 / 手机休眠**不保证定时任务运行。
- 本仓库**不声称**已在真实数据环境部署；**源码已公开**（`github.com/ABGanBei/jiuguan-github-sync`），但「源码发布」与「真实数据同步验收」是**不同事项**——真实聊天数据在真实 GitHub 上的端到端同步**尚未验收**。各套测试通过数量以 Codex 实测证据为准，本说明不写死具体数字。
- 本仓库**不声称已做加密**：令牌经独立 secrets 存储与 `GIT_ASKPASS` 传递、不进日志/URL/参数，但并非加密存储。
- Windows 凭据当前以 DACL 收紧到当前用户 / SYSTEM / Administrators（SID），无法进一步按 POSIX 语义收紧。
