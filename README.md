# 酒管 GitHub 同步

[English](README_EN.md) | 中文

**第一次使用请看[新手使用说明](docs/quickstart.md)。**

**1.4 统一安装向导版**：把当前用户已保存的一对一角色聊天正文备份到专用 GitHub 私有仓库，在另一台设备检查并暂存，关闭所有客户端、手动重启服务后应用。

## 支持范围

- 酒管 **1.17.x**，**Node.js 20+、npm、Git**。旧版酒管请先备份并自行升级，向导不会升级酒管。
- 只同步 `chats/**/*.jsonl` 一对一聊天正文；角色卡、世界书、群聊、附件和设置不同步。两端要有相同角色卡，实际卡文件名也须一致。
- 上传处理当前用户全部已保存的一对一聊天。检查更新只暂存；不在线覆盖、不强制推送、不传播删除。
- 冲突保留双方，交由用户处理；本版没有聊天加密和 Git 历史清理。

## 安装与升级

从[本仓库](https://github.com/ABGanBei/jiuguan-github-sync)下载并解压本版，或克隆到新目录。先关闭全部酒管页面和客户端并停止服务，然后：

- **Windows：双击 `install.cmd`。**
- **Termux：在源码目录运行 `bash setup.sh`。**

向导选择酒管目录，打印安装计划，确认后一起安装前端扩展和后台插件、安装依赖、启用服务端插件。完成后自行启动服务并打开全新页面，无需再分别安装两个组件。Termux 尚未完成真机验收。

可识别的旧版本会先备份再升级；同版本且内容一致时不重复安装。未知来源、被修改或无安装清单的旧目标默认拒绝，只有显式 `--takeover` 才会先完整备份再接管。用户级同名扩展会覆盖共享扩展，发现提示时先处理该用户级扩展。

命令行入口也使用同一向导。交互模式先展示计划再确认；非交互实际安装要求同时给出 `--apply --stopped-confirmed`：

```text
node bin/setup.js --app-dir "酒管目录"
node bin/setup.js --app-dir "酒管目录" --config "实际config.yaml路径" --data-root "实际数据根目录" --apply --stopped-confirmed
```

`--stopped-confirmed` 是你已关闭所有客户端并停服的声明，向导不会自动停服或重启。非交互安装必须明确指定数据根；仅在了解遮蔽风险时用 `--no-data-root` 明确跳过扫描。

安装中断时，保留 `<酒管目录>/.jiuguan-install/`，先查状态，再选择恢复或回滚：

```text
node bin/setup.js --status --app-dir "酒管目录"
node bin/setup.js --recover --app-dir "酒管目录" --stopped-confirmed
node bin/setup.js --rollback --app-dir "酒管目录" --stopped-confirmed
```

恢复和回滚都要求先停服。回滚可用 `--to <backupId>` 指定备份；历次备份不自动删除，回滚后新版目录移入隔离目录保留。更多参数见 `node bin/setup.js --help`。

使用外置配置时，恢复和回滚都要加上 `--config "原来的实际config.yaml路径"`；安装器不会仅凭日志中的路径写外部文件。

## 首次设置

1. 在 [GitHub 网页](https://github.com/new)创建**专用 Private 数据仓库**，不添加 README、`.gitignore` 或 License。
2. 创建[细粒度 PAT](https://github.com/settings/personal-access-tokens/new)：`Only select repositories` **只选这个数据仓库**，`Contents: Read and write`，`Metadata` 保持默认只读；无需其他权限。
3. 面板里填写 `owner/repo`、分支（默认 `main`）和令牌，点 **「保存并验证」**。另一台使用同一个仓库和分支，各自填写有权限的令牌。
4. 若分支不存在，核对目标后单独确认初始化。它只普通推送一个不含聊天的提交，不强制覆盖。
5. 查看验证结果，再开始第一次上传或检查更新。

**本仓库是公开的插件源码仓库，不能用来存聊天。** 私有性与读取验证成功只说明已核对仓库并能读取；写入只有在**实际初始化或实际上传成功**后确认。权限设置和读取成功均不等于推送成功，分支保护等规则仍可能阻止推送。

PAT 保存后清空且不回填，留空保留已有令牌。仓库和分支有同步状态后锁定，可换令牌并重新验证。

## 每天怎么用

| 操作 | 结果 |
| --- | --- |
| **上传已保存聊天** | 等生成、保存完成后，上传磁盘上已保存的聊天。 |
| **检查更新** | 下载并暂存远端更新，不改写当前聊天。 |

换设备时：原设备上传成功 → 新设备检查更新 → 查看待更新列表并通过预检 → 关闭其他客户端并勾选确认 → **安排应用（重启后）** → 关闭当前页面 → **手动停止并重新启动酒管服务** → 打开全新页面，确认应用状态再继续聊天。

预检只反映检查时点，安排和启动时还会再次核对；安排成功不代表已应用，刷新网页不算重启服务。上传结果中的“远端更新候选，尚未下载”也不等于已有暂存，仍需检查更新。

自动检查默认关闭，设置折叠在面板中。开启后只定时检查并暂存，不上传、不在线覆盖、不自动应用；已安排应用时保留该暂存。服务关闭或手机休眠时不保证运行。面板显示最近检查、上传和应用记录。

## 数据与凭据

- 聊天以明文进入私有仓库的 Git 历史，删除当前文件不会删除旧提交。私有访问控制不提供端到端加密。
- PAT 放在独立 secrets 存储，通过 `GIT_ASKPASS` 传递，不进入普通配置、日志、仓库、URL 或进程参数；令牌存储本身未加密。
- Windows 凭据 DACL 限制为当前用户、SYSTEM 和 Administrators；各用户使用独立配置、仓库与锁。
- 应用前核对暂存身份、内容和本地状态，先备份再写入；冲突或校验失败时保留数据并阻断。完成后若崩溃导致缺少匹配的执行凭据，会保留安排并显示“无法确认”，不会从旧历史猜测成功。
